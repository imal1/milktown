# 版本历史：时间机器与双页对比

> **前置依赖**：spec 01（Vue + Crepe + Tauri 重写）必须先完成。本 spec 假定编辑器持有文档、文件读写走 Tauri 插件、1c 界面已就位。

## Problem Statement

写作是不断推翻自己的过程。一段话被删掉之后就没了——用户想找回三小时前那个版本里的某个句子，唯一的办法是记得自己当时写了什么。

现有的补救办法都不合用。给散文用 git 意味着写作时被要求停下来写提交信息，而写作没有「一次逻辑变更」这样的边界，心流会被打断。系统层面的时间机器粒度太粗、翻找太慢，且和正在写的那个窗口毫无关系。

用户想要的是：写就完了，历史自己攒着；想找回什么的时候，能翻回去看，能看出两个时刻之间**到底改了什么**。

## Solution

保存时自动留存版本，用户不写任何提交信息、不接触任何 git 概念。

需要回看时，用快捷键进入**双页视图**：窗口被完全接管，并排显示当前内容与某个历史版本，两者之间的差异以行级增删标出。选择版本、看完、按 Esc 回到写作。

第一阶段只做**单个文件**的历史。以目录 / 仓库为单位的版本、以及届时引入真 git，是明确的第二阶段（ADR 0004）。

版本存放在文件旁边的隐藏目录里，跟着文件走（ADR 0005）。差异显示的是 Markdown 源码的行级差异，并因此要求所有文本先经过规范化（ADR 0006）。术语一律使用 `CONTEXT.md` 中「版本 / 历史 / 规范化 / 双页视图」的定义。

## User Stories

1. 作为写作者，我想在按 ⌘S 时自动留存一个版本，以便我不必为了留痕而做任何额外操作。
2. 作为写作者，我想连续按几次 ⌘S 不会产生几个几乎相同的版本，以便历史里没有噪音。
3. 作为写作者，我想在写作超过一段时间后的保存产生一个新版本而不是覆盖上一个，以便历史的密度和我实际的写作节奏一致。
4. 作为写作者，我想在打开一个文件时无条件留存一个版本，以便我有一个「我今天开始动它之前」的锚点。
5. 作为写作者，我想在关闭一个文件前无条件留存一个版本，以便我最后的状态一定被记下来。
6. 作为写作者，我想用一个快捷键进入历史，以便回看不需要在界面上找入口。
7. 作为写作者，我想进入历史后整个窗口被接管，以便我能用满屏幕看两个版本。
8. 作为写作者，我想按 Esc 从历史回到写作，以便退出的方式和关闭其它浮层一致。
9. 作为写作者，我想在历史里看到这个文件的所有版本，按时间倒序排列，以便最近的改动最容易找到。
10. 作为写作者，我想每个版本显示它留存的时间，以便我用「大概是午饭前」这样的记忆去定位。
11. 作为写作者，我想用方向键在版本之间移动，以便我快速扫过整段历史。
12. 作为写作者，我想选中一个版本后立刻看到它与当前内容的差异，以便我不必再点一次「比较」。
13. 作为写作者，我想差异以增行和删行的形式标出，以便我一眼看到哪几行动过。
14. 作为写作者，我想两页可以一起滚动，以便长文档里的对照不需要我分别操作两侧。
15. 作为写作者，我想在两个版本之间没有任何差异时被明确告知，以便我不用盯着两屏一样的内容找不同。
16. 作为写作者，我想从历史里把某个版本的内容整体还原回编辑器，以便我能真的回到过去。
17. 作为写作者，我想在还原会覆盖未保存的修改时被拦下来问一句，以便我不会用一次还原丢掉刚写的东西。
18. 作为写作者，我想还原之后当前文档变成脏状态而不是被直接写回磁盘，以便我还有反悔的机会。
19. 作为写作者，我想还原这件事本身也留下一个版本，以便「我还原过」这件事在历史里可见。
20. 作为写作者，我想只从历史里复制某一段而不是整体还原，以便我取回一个句子时不牺牲其它改动。
21. 作为写作者，我想历史跟着文件走，以便我备份笔记目录时历史一起被备份。
22. 作为写作者，我想我的笔记目录本身在 git 里时，历史也能被 git 一起提交，以便两套记录不冲突。
23. 作为写作者，我想版本存放在隐藏目录中，以便它不干扰我在访达里浏览笔记。
24. 作为写作者，我想从别的编辑器带来的文件在 milktown 里保存一次之后，格式被统一成固定的写法，以便此后的差异只反映内容变化。
25. 作为写作者，我想打开一个外来文件时应用不擅自改写它，以便「打开」这个动作是安全的、只读的。
26. 作为写作者，我想第一次保存一个外来文件时那次格式统一不会淹没历史，以便我不必在满屏格式噪音里找我的实际改动。
27. 作为写作者，我想无序列表统一用同一个符号、加粗斜体统一用同一种写法，以便我的所有文件风格一致。
28. 作为写作者，我想这套格式和主流工具（Prettier）的默认写法一致，以便我的文件被别的工具处理时不会产生无谓的改动。
29. 作为写作者，我想在磁盘写入失败时被明确告知，以便我知道这次没有留下版本。
30. 作为写作者，我想历史目录被外部删除后应用仍能正常工作，以便丢历史不至于让我打不开文件。
31. 作为写作者，我想历史目录里出现无法识别的内容时应用跳过它而不是崩溃，以便手工乱动过目录也不会让应用不可用。
32. 作为写作者，我想在文件从未保存过（没有路径）时进入历史会得到一句清楚的说明，以便我理解为什么这里是空的。
33. 作为写作者，我想留存版本不让我的保存变慢到有感，以便 ⌘S 依然是一个瞬间完成的动作。

## Implementation Decisions

**一条缝：历史模块**

本功能的全部逻辑集中在一个模块后面，对外暴露五个操作：

- **打开文件** —— 输入文件路径与磁盘上的原始文本；在内存中计算规范化文本作为该次会话所有差异计算的基线，并读取已有历史。**不写盘。**
- **保存** —— 输入文件路径、编辑器当前的 Markdown、当前时刻；执行规范化，按留存策略决定新增版本还是覆盖上一个版本，写入磁盘，返回结果版本。
- **列出历史** —— 输入文件路径，返回按时间倒序排列的版本列表。
- **读取版本** —— 输入文件路径与版本标识，返回该版本的完整文本。
- **比较** —— 输入两段文本，返回行级差异。

规范化的幂等性、留存策略的时间窗口、隐藏目录的布局、行级差异的计算，全部关在这条缝后面，模块之外不可见。

**两个注入的端口**

- **时钟** —— 生产环境读系统时间；测试环境可控。留存策略依赖时间窗口，不注入时钟就无法测试。
- **文件系统** —— 生产环境是 Tauri 的文件系统插件；测试环境是内存实现。

**留存策略**（ADR 0004）

保存时留存一个版本；若距上一个版本不足 5 分钟则覆盖它而非新增。打开文件与关闭文件两个时刻无条件新增一个版本，不受时间窗口约束。版本存储的是完整内容而非增量——单个 Markdown 文件的体积下，增量存储是过早优化。

**存储布局**（ADR 0005）

版本存放在目标文件所在目录下的隐藏目录中，按所属文件与留存时刻组织，使同一目录下多个文件的历史互不干扰。布局的具体形状由实现决定，但必须满足：可从单个文件路径定位到它的全部版本；可从版本条目还原出留存时刻；人工检视时可读；损坏或无法识别的条目被跳过而不是导致整体失败。

应用不修改用户的 git 配置——是否把隐藏目录加入忽略列表由用户自行决定。

**规范化**（ADR 0006）

规范化必须使用 **Milkdown 实际的解析器与序列化器**，不能用裸 remark 或任何其它 Markdown 工具。要消除的是 Crepe 自身的往返差异，用别的工具算出的不动点与 Crepe 的不是同一个。

序列化风格通过 Milkdown 暴露的序列化选项钉死：无序列表用 `-`；斜体用 `_`；加粗用 `**`；代码围栏用反引号；分隔线用 `---`；标题用 ATX 形式；有序列表编号递增；块之间一个空行；文件末尾一个换行。整体对齐 Prettier 的 Markdown 默认值。

打开文件时计算的规范化基线只存在于内存中，直到用户第一次保存才落到磁盘。打开一个文件不得改写它。

**差异计算**

在两段**已规范化**的文本之间做行级差异，产出增行、删行与未变行的序列。差异从不在未规范化的文本上计算——否则格式噪音会淹没内容变化。

**双页视图**

进入方式为快捷键；后续会在系统菜单栏中增加一个可见入口，那部分不在本 spec 内。进入后接管整个窗口：一侧为选中的历史版本，一侧为当前内容，差异标注其上，两侧滚动联动。Esc 退出。

**这个视图不含业务逻辑**：它渲染历史模块返回的版本列表与差异结果，并把用户的选择、还原、退出意图发出去。

**还原**

还原是把某个版本的文本装回编辑器，使文档变脏，**不直接写回磁盘**。若当前有未保存的修改，还原前必须确认。还原动作本身会在下一次保存时留下版本，使「曾经还原过」在历史中可见。

**1c 界面不受影响**

标题栏仍然只有交通灯、文件名按钮、字数三样东西，不为本功能新增任何常驻控件。

## Testing Decisions

**什么是好测试**：只测这条缝的外部行为。测「相隔 4 分钟的两次保存之后历史里只有一个版本」，不测模块内部用什么数据结构记录时间。测试绝不触碰真实磁盘，也不依赖真实时间流逝。

**被测模块**：历史模块，通过其五个对外操作驱动，注入可控的时钟与内存文件系统。

覆盖的行为至少包括：

- 规范化是幂等的——对已规范化的文本再次规范化，结果不变。
- 规范化把各种等价写法收敛到同一形式（列表符号、强调符号、围栏字符、标题形式、块间空行、末尾换行）。
- 内容未变时，两个版本之间的差异为空。
- 只改一行时，差异只报告那一行。
- 相隔不足 5 分钟的两次保存，历史中只留一个版本，且内容是后一次的。
- 相隔超过 5 分钟的两次保存，历史中留下两个版本。
- 打开文件与关闭文件无条件新增版本，即使距上一个版本不足 5 分钟。
- 打开文件不产生任何磁盘写入。
- 历史按时间倒序返回。
- 历史目录不存在时，列出历史返回空而不是报错。
- 历史目录中存在无法识别的条目时，该条目被跳过，其余版本正常返回。
- 磁盘写入失败时错误被抛出，不被静默吞掉。
- 同一目录下两个不同文件的历史互不干扰。

**双页视图不设测试缝**——其中不含逻辑。

**prior art**：本项目此前没有测试。spec 01 会引入测试框架，本 spec 沿用它，不另立一套。

## Out of Scope

- **真 git** —— 明确是第二阶段（ADR 0004）。当前阶段不引入任何 git 库，不写 `.git` 目录，不产生提交。
- **以目录 / 仓库为单位的版本** —— 同上，第二阶段。
- **双页视图对比任意两个不同文件** —— 第二阶段。当前双页只显示同一文件的两个版本。若实现此功能，单文档模型需要重新审视。
- **渲染层的差异显示**（在渲染后的富文本上标注增删）—— 已评估并否决，理由见 ADR 0006。块级差异是日后可选的升级路径，不在本次范围。
- **版本的命名、标注、收藏** —— 时间机器不要求用户为版本赋予意图，加了就变成「命名存点」，那是被否决的产品形态。
- **历史的清理与容量上限** —— 当前不做。若日后需要，在历史模块内部实现，接口不变。
- **跨设备同步历史** —— 依赖用户已有的备份方案（ADR 0005），应用不介入。
- **系统菜单栏中的入口** —— 后续阶段。
- **外部文件变更的监听** —— 应用之外移动或重命名文件会让历史断在原处，这是 ADR 0005 已接受的代价。

## Further Notes

本功能最大的风险不在存储也不在差异算法，而在**规范化能否脱离浏览器环境运行**。历史模块必须调用 Milkdown 实际的解析器与序列化器，而那套代码是否需要 DOM 尚未实测。若它无法在无浏览器的测试环境中运行，这条缝要向上抬到「在真实编辑器实例中执行」，测试会显著变慢。**这一点应在动手写存储与差异逻辑之前先验证**，它决定整个模块的形状。

差异显示 Markdown 源码，对一个所见即所得编辑器是一次自觉的产品让步。已在 ADR 0006 中记录理由与升级路径——收到「diff 太刺眼」的反馈时，先读那份 ADR，不要重新讨论一遍。
