# 重写：Vue 3 + Milkdown Crepe + Tauri 原生文件读写

## Problem Statement

milktown 现在是一个打不开、也存不下文件的 Markdown 编辑器。

用户点「打开」，弹出的是浏览器的文件选择框，读进来的内容没有路径，只有一个文件名字符串。用户点「保存」，触发的是浏览器下载——在一个桌面应用里弹出一个下载。用户回不到原文件，改不了原文件。

更糟的是，用户在编辑器里打的字**根本没有进入保存流程**。编辑器的内容变化从未传回应用，所以「已修改」标记永远不亮，而保存写出去的是应用启动时那段内置的示例文本。用户以为自己保存了一小时的写作，实际存下来的是一份模板。

对一个 Markdown 编辑器来说，这意味着它的核心任务一件都完不成。

## Solution

把前端整个重写：Vue 3 + Milkdown Crepe，通过 Tauri 的文件系统与对话框插件接通真实的本地文件读写。

用户打开一个 `.md` 文件，看到的是渲染后的样子（所见即所得），带斜杠命令菜单、选中文字的浮动格式条、表格手柄、代码块语言选择。用户写完按 ⌘S，内容写回**原来那个文件**。文件名旁的 `*` 如实反映是否有未保存的修改。关掉再打开，最近文件列表把用户带回昨天写到一半的那篇。

界面遵循已定稿的 1c 克制方案：没有工具栏，只有一条 34px 的标题栏，把屏幕留给文字。

选型与理由见 ADR 0001（为什么是 Vue + Crepe，以及被否决的四条路）和 ADR 0002（为什么编辑器持有文档）。术语一律使用 `CONTEXT.md` 的定义。

## User Stories

1. 作为写作者，我想打开电脑里任意一个 `.md` 文件，以便继续编辑我已有的笔记。
2. 作为写作者，我想通过系统原生的文件选择对话框来选文件，以便用我熟悉的方式浏览目录、看到收藏夹和最近位置。
3. 作为写作者，我想让打开的文件以渲染后的样子呈现，以便我看到的就是最终的样子，不必在脑子里编译 Markdown。
4. 作为写作者，我想按 ⌘S 把修改写回**原来那个文件**，以便我的编辑真的落在磁盘上。
5. 作为写作者，我想在文件从未保存过时，按 ⌘S 弹出系统的保存对话框让我选位置和文件名，以便新文档也能落盘。
6. 作为写作者，我想通过 ⇧⌘S 另存为一个新文件，以便我在不动原文件的前提下分叉出一个版本。
7. 作为写作者，我想按 ⌘N 开始一篇空白文档，以便我随手记下一个突然冒出来的想法。
8. 作为写作者，我想在当前文档有未保存修改时新建或打开另一个文件会被拦下来问一句，以便我不会静默丢掉刚写的东西。
9. 作为写作者，我想在标题栏中央看到当前文件名，以便我随时知道自己在写哪一篇。
10. 作为写作者，我想在有未保存修改时看到文件名后面出现 `*`，以便我一眼确认是否需要按 ⌘S。
11. 作为写作者，我想在保存成功后看到 `*` 立刻消失，以便我确信保存真的发生了。
12. 作为写作者，我想在保存成功后看到一个短暂的提示浮现在窗口底部并自动消失，以便我得到确认但不被打断。
13. 作为写作者，我想在标题栏右侧看到当前字数，以便我掌握篇幅而不必另开工具。
14. 作为写作者，我想点击标题栏中央的文件名展开一个最近文件面板，以便我不用走文件对话框就能跳回常写的几篇。
15. 作为写作者，我想在最近文件面板里用上下方向键选择、回车打开，以便我的手不必离开键盘。
16. 作为写作者，我想用 Esc 关掉最近文件面板，以便我误触后能立刻回到写作。
17. 作为写作者，我想按 ⌘O 直接唤出最近文件面板，以便我用一个快捷键完成最常见的切换。
18. 作为写作者，我想在最近文件里看到每个文件所在的目录和最后打开的时间，以便我在多个同名文件之间分辨出要的那个。
19. 作为写作者，我想在打开一篇空白新文档时，屏幕上直接显示最近文件列表，以便空状态本身就是一个入口而不是一片虚无。
20. 作为写作者，我想在开始打字后最近文件列表立刻消失，以便它不干扰写作。
21. 作为写作者，我想我的最近文件列表在应用重启后仍然存在，以便我第二天回来能接着写。
22. 作为写作者，我想在文档里用斜杠唤出插入菜单，以便我不记 Markdown 语法也能插入标题、列表、代码块、表格。
23. 作为写作者，我想选中一段文字后浮出格式工具条，以便我一键加粗、变斜体、加链接。
24. 作为写作者，我想在代码块上选择语言并看到语法高亮，以便我贴的代码是可读的。
25. 作为写作者，我想用手柄拖动调整表格的行列，以便我不必手写 Markdown 表格的对齐语法。
26. 作为写作者，我想任务列表的复选框可以直接点击勾选，以便我把文档当清单用。
27. 作为写作者，我想公式以渲染后的样子显示，以便我写技术笔记时能看到结果。
28. 作为写作者，我想在空文档里看到一句占位提示，以便我知道可以直接开始打字。
29. 作为写作者，我想正文以衬线字体、限定行宽、宽松行距呈现，以便长时间阅读和写作不累眼。
30. 作为写作者，我想窗口没有工具栏，以便屏幕高度全部留给文字。
31. 作为写作者，我想窗口使用自绘的标题栏而不是系统默认边框，以便应用的视觉是完整的一体。
32. 作为写作者，我想在打开一个文件后撤销历史是干净的，以便我不会误撤销到上一篇文档的内容。
33. 作为写作者，我想应用启动很快，以便我想记一件事时它已经准备好了。
34. 作为写作者，我想在打开一个不存在或没有读取权限的文件时看到清楚的说明，以便我知道是路径的问题而不是应用坏了。
35. 作为写作者，我想在保存失败（比如磁盘满或没有写权限）时被明确告知且 `*` 不消失，以便我不会误以为已经保存。
36. 作为写作者，我想最近文件列表里已经不存在的文件被标出来或在打开失败时被移除，以便列表不会积累死链接。

## Implementation Decisions

**技术栈与依赖变更**

前端从 React 全线改为 Vue 3。删除 `react`、`react-dom` 及其类型定义、`@vitejs/plugin-react`、`@milkdown/react`、`@prosemirror-adapter/react`、`@milkdown/theme-nord`。新增 `vue`、`@vitejs/plugin-vue`、`@tauri-apps/plugin-fs`、`@tauri-apps/plugin-dialog`。升级 `@milkdown/crepe`、`vite`、`typescript`。

**不安装 `@milkdown/vue`。** 那个包是裸 Milkdown Kit 的 Vue 绑定；Crepe 是一个 vanilla class，在 Vue 组件里用模板引用加挂载钩子直接实例化即可。

TypeScript 7 是硬约束，见 ADR 0003——遇到工具链问题的解法是让 TS 7 跑通，不是降级。若 `vue-tsc` 在 TS 7 下不可用，去掉 `vue-tsc`，不降 TypeScript，也不为迁就它放弃单文件组件写法。

**Rust 侧不新增代码。** `tauri-plugin-fs` 与 `tauri-plugin-dialog` 已在 `Cargo.toml` 中注册、capabilities 已授权，本次只补前端的 JS 绑定。`lib.rs` 保持只有脚手架自带的示例命令。（此前「一行 Rust 都不写」是一条推荐而非用户约束；本 spec 的范围内确实不需要 Rust，但这不构成对未来的禁令。）

**模块划分**

- **编辑器模块** —— 封装 Crepe 的生命周期：挂载、销毁、取出当前 Markdown、订阅文档变更。对外只暴露这四件事，Crepe 的实例不外泄。十个 feature 全部开启，不做裁剪。
- **文件模块** —— 打开（唤起对话框、读文本、返回路径与内容）、保存到指定路径、另存为（唤起保存对话框）。它只处理路径与文本，不认识编辑器。
- **最近文件模块** —— 维护一个按最近打开时间排序的路径列表，持久化到浏览器本地存储。提供记录一次打开、读取列表、移除某一项三个操作。
- **应用状态** —— 只持有当前文件路径、脏标记、字数。**不持有文档内容**（ADR 0002）。
- **界面组件** —— 标题栏、写作区、最近文件面板、提示浮层、空状态。这些组件不含业务逻辑，只渲染状态、发出意图。

**关键契约**

- 文档内容的唯一真相源是编辑器实例。保存时向编辑器索取当前 Markdown，绝不从应用状态里取。
- 打开另一个文件时销毁旧编辑器实例、以新内容创建新实例。撤销历史随之清空，这是刻意行为。
- 脏标记由编辑器的文档变更事件置位，由一次成功的保存清零。不通过比对内容判定。
- 全局快捷键只注册一处。此前 `Editor` 与 `Toolbar` 各注册一份 ⌘S 监听器互相竞争，不得重现。
- 组件之间不通过查询 DOM 互相触发。此前应用组件靠 CSS 类名查到工具栏按钮再模拟点击，这类跨组件穿刺一律禁止。
- 保存失败必须向上抛出并保持脏标记不变。

**界面**

严格遵循 `docs/design/project/Milktown 原型.dc.html`（1c 克制方案）：34px 标题栏，左侧交通灯，中央文件名按钮（点击展开最近文件，脏时后缀 `*`），右侧字数；写作区居中、行宽 66ch、正文 18px、行高 1.8、衬线正文配等宽元信息；最近文件面板从标题栏下方浮出；提示浮层在窗口底部居中，约 1.8 秒后消失。窗口无系统边框，标题栏自绘。

**快捷键**

⌘S 保存 · ⇧⌘S 另存为 · ⌘N 新建 · ⌘O 最近文件 · Esc 关闭浮层。

## Testing Decisions

**什么是好测试**：只测外部行为，不测内部实现。测「保存后脏标记消失」，不测「某个内部变量被赋了什么值」。测试不应知道模块内部用了哪个库、状态存在哪个字段里。

**缝的位置**：本次的可测逻辑集中在两处，都在 UI 之下：

- **文件模块** —— 注入一个文件系统实现（生产环境是 Tauri 插件，测试环境是内存实现）和一个对话框实现（测试环境返回预设路径）。可测：打开返回正确的路径与内容；保存写到正确路径；未保存过的文档触发另存为流程；读写失败被正确抛出。
- **最近文件模块** —— 注入一个键值存储实现。可测：新打开的文件排到最前；重复打开同一文件不产生重复项；列表长度上限被遵守；不可用的存储不导致崩溃。

**编辑器模块与界面组件不设测试缝。** 编辑器模块几乎全是对 Crepe 的委托，测它等于测 Crepe；界面组件里不放逻辑，因此没有值得测的行为。

**本项目目前没有任何测试，也没有测试框架。** 本次需要引入一个——选型不在本 spec 内预先钉死，但要求：能在 Vite 8 与 TypeScript 7 下运行，无需浏览器环境即可跑上述两个模块的测试。

## Out of Scope

- **版本历史与双页视图** —— 见 spec 02，那份 spec 依赖本 spec 完成。
- **目录 / 工作区 / 文件树 / 标签页** —— 单文档模型下明确不做。
- **系统菜单栏** —— 后续阶段。本次快捷键直接在窗口内注册。
- **主题切换与深色模式** —— 本次只实现 1c 定稿的浅色样式。
- **拖拽文件打开、搜索替换、设置界面** —— README「开发计划」中的遗留条目，均不在本次范围。
- **本地相对路径图片的显示** —— 已知问题：webview 默认加载不了本地相对路径图片，需配置 Tauri 的 asset protocol。本次不解决，但插入图片的其它路径不应因此崩溃。
- **跨平台验证** —— 本次只保证 macOS 可用。
