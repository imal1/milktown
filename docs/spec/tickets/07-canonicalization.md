## What to build

一个把任意 Markdown 收敛到固定书写形式的**规范化模块**：文本 → 文档 → 文本，同一份内容经规范化后总是得到完全相同的文本。

**这张票排在版本功能最前面是有意的。** 规范化必须调用 Milkdown 实际的 parser 与 serializer，而那套代码能否脱离浏览器 DOM 运行尚未实测。答案决定整个历史模块的缝放在哪里——跑不通就要把缝抬到「在真实编辑器实例中执行」，测试会显著变慢。这个问题必须在写存储和差异逻辑之前撞上，不能埋到实现中途。

## Acceptance criteria

- [ ] 规范化使用 **Milkdown 实际的 parser 与 serializer**，不使用裸 remark 或任何其它 Markdown 工具（要消除的是 Crepe 自身的往返差异，别的工具算出的不动点不是同一个）
- [ ] 序列化风格按 ADR 0006 钉死：无序列表 `-`、斜体 `_`、加粗 `**`、代码围栏用反引号、分隔线 `---`、ATX 标题、有序列表编号递增、块间一个空行、文件末尾一个换行
- [ ] 幂等：对已规范化的文本再次规范化，结果不变
- [ ] 收敛：各种等价写法被收敛到同一形式（列表符号、强调符号、围栏字符、标题形式、块间空行、末尾换行）
- [ ] **明确回答规范化能否脱离浏览器环境运行**，并把结论记录下来。若不能，在本票内提出缝的新位置供确认，不要自行改变后续票的形状
