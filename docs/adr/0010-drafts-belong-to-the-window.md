# 草稿属于窗口，且只有落盘之后才删

一个从未保存过的文档，在窗口被关闭时把完整内容留存下来，这份留存叫**草稿**。下次空手启动时草稿被装回编辑器，装回来的文档仍然是脏的、仍然没有当前文件。

草稿不是自动保存：它只服务于「没有文件可写」这一种情况。有当前文件的脏文档在关窗时走的是确认对话框（`⏎` 保存 · `⌘D` 不保存 · `Esc` 取消），那条路已经有归宿了，不需要草稿。

**一个窗口一份草稿。** 关了三个未保存的窗口就有三份草稿，下次启动开三个窗口，各自装回各自那份。草稿以窗口为单位而不是全局一份，是因为它是「这个编辑会话的内容」的容身处，会话本来就是按窗口划分的（CONTEXT.md）。

## 生命周期

- **写入**：窗口关闭时，若文档是脏的且没有当前文件。
- **删除**：那份内容真正存成文件之后。**不在恢复的那一刻删**——恢复即删等于把用户仅有的一份内容押在「这次会话不会崩」上。
- **再次关窗仍未保存**：重新落一份，覆盖原来那份。草稿因此可能永远删不掉，这是对的，它就是那份内容唯一的容身处。
- **双击文件启动**时文件优先，草稿留着不动，此时不额外开窗恢复草稿，留到下次空手启动。

## 空状态

零草稿时开一个空窗口，显示最近文件列表；有 N 份草稿时开 N 个窗口，全都不显示空状态。空状态与草稿互斥。

## Consequences

- 草稿存在 local storage 里，与最近文件同处（ADR 0007）。它不进 `.milktown/`——那里存的是版本，版本属于文件，草稿恰恰是没有文件的那种东西（ADR 0005）。
- 一份长期不保存又反复被恢复的草稿会一直占着一个启动窗口。可接受：用户自己按 ⌘S 或 ⌘W 就能了结它。
