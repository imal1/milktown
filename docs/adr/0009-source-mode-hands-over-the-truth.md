# 源码模式是真相源的一次交接，不是第二个真相源

⌘/ 进入源码模式时，Crepe 编辑器实例被销毁，它持有的 Markdown 原文被放进一块纯文本编辑区；再按 ⌘/ 退出时，文本区的内容被解析成文档、创建新的编辑器实例，文本区被销毁。任何时刻只有一方持有文档。

这是 ADR 0002 的延续而不是例外。0002 禁止的是「Vue state 和编辑器各存一份内容并双向同步」，那条禁令的理由是同步会漂移。交接不同步：旧的一方在新的一方接手时就不存在了，没有第二份内容可以漂移。

## Considered Options

- **编辑器与文本区同时存在、双向同步** —— 这正是原实现失败的形状（0002 记录的 React state / Milkdown 双写）。写作视图与源码视图的实时联动看起来很值钱，但它要求每一次按键都做一轮「解析 → 序列化」并把光标映射回去，而这套映射恰恰是 ADR 0006 里那条已经放弃的路（`prosemirror-recreate-steps`）。拒绝。
- **源码模式只读** —— 不解决问题。用户进源码模式就是为了改那些所见即所得改不动的东西。
- **交接** —— 采纳。

## 保存路径就此分岔

源码模式下的 ⌘S 写出的是文本区里的原文，**不经过规范化**。写作视图下的 ⌘S 仍然写规范化文本（ADR 0006）。

这意味着 ADR 0006 里「规范化后的文本是本应用唯一认可的书写形式」这句话不再成立，该 ADR 已相应修订。规范化从「文件的全局不变量」降格为「所见即所得这条保存路径的序列化风格」。代价是：源码模式保存过的文件，其下一次版本对比可能出现纯格式差异。这是用户手动进入源码模式换来的，与「打开别处的文件时不擅自改写」是同一个原则——用户明确表达的意图优先于应用的整洁。

版本存的同样是原文：ADR 0004 的版本是「文件在某一时刻的完整内容留存」，留存的必须是真正落盘的那份字节，否则历史里的版本与文件本身对不上。

## 脏标记与模式切换

- 文本区的 `input` 事件与编辑器的文档变更事件同级，都置脏（ADR 0002 的规则不变，只是多了一个来源）。
- **纯粹的模式切换不置脏**，即使退出源码模式时的重新解析改变了文本。切换不是编辑。这与 0006 的「打开文件时在内存中规范化、不写盘、不置脏」是同一条规矩。

## 其余行为

- **字数**统一口径为**原文字符数**（去掉首尾空白）。源码模式直接数文本区长度；写作视图从编辑器序列化出 Markdown 再数，节流 300ms。数字在 ⌘/ 前后不跳变，代价是写作视图的字数把标记符号也算进去了——口径稳定比口径精确重要。
- **⇧⌘H 在源码模式下先自动退回写作视图**，再进双页视图，退出后停在写作视图。双页视图的差异本来就是源码级的（0006），源码模式叠在它上面没有增量意义；这样「把版本装回编辑器」永远只有一个目的地。
- **Tab 在文本区插入两个空格**，不移出焦点。源码模式的全部用途就是改文本，窗口里也没有第二个可聚焦的东西。
- **查找条的「全部替换」算一步撤销**：用 `setRangeText` 一次性改写，保留文本区的原生撤销栈。

## Consequences

- 进出源码模式会清空撤销历史，两边各有各的栈。与「打开另一个文件即结束编辑会话」（CONTEXT.md）一致。
- 文本区没有语法高亮。加高亮意味着引入一个代码编辑器（CodeMirror 之类），那是一个比本 ADR 大一个量级的决定，留待真的觉得难读时再做。
- 「让两个视图实时联动」的改动是在恢复已知会失败的设计，与 0002 的末条同等对待，不要做。
