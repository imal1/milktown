# 文件进入应用的四条路，以及它们各自的严格程度

单文档模型说的是一个窗口一个文档，不是一个应用一个窗口。文件从四个地方进来：

1. **Finder 双击 / `open` 命令** —— 开一个新窗口装这个文件。
2. **命令行参数** —— 同上。
3. **拖进窗口** —— 装进当前窗口（当前文档若是脏的，先走确认对话框）。
4. **⌘O 最近文件 / ⇧⌘O 打开对话框** —— 装进当前窗口，行为不变。

**同一个文件已经在别的窗口开着时，静默聚焦那个窗口**，不开第二个窗口、不弹提示。两个窗口编辑同一个文件会让「谁的 ⌘S 说了算」变成一个没有好答案的问题，直接不允许它发生。

## 认哪些后缀

`.md` `.markdown` `.mdown` `.mkd` `.txt`

`.txt` 收进来是因为它必然会被拖进来，而 Markdown 是纯文本的超集，打开它不会坏事。

**文件关联只注册 `.md`**（`tauri.conf.json` 里），不去抢 `.txt` 的默认打开方式；**拖拽与命令行接受整份清单**。两者严格程度不同是刻意的：关联是抢占，用户没有在当场表态；拖拽是用户当场的明确意图。悬停时后缀不在清单里的，提示「不认识 .png」并拒绝落下。

## 窗口菜单

多窗口一旦成立，系统菜单栏里就得有「窗口」菜单——列出所有已开窗口、⌘M 最小化、窗口间切换。这是 macOS 用户对多窗口应用的最低期待，不属于「工具栏」那类被本项目刻意砍掉的东西。

## Consequences

- 单例应用：第二次启动把参数交给已运行的实例，由它开窗口，而不是起第二个进程。
- 最近文件是全局的，不按窗口分（ADR 0007 不变）。
- 版本存在文件旁边（ADR 0005），与哪个窗口打开它无关。
