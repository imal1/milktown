# 版本存在文件旁边，不存在应用数据目录

一个文件的历史存放在它所在目录下的隐藏目录里（形如 `~/notes/.milktown/`），而不是集中存放在 `appDataDir()`。

这是本功能最难逆转的一条决定：用户数据一旦按某种布局落盘，再想搬动就要写迁移。

理由三条：

1. **对齐未来的真 git。** ADR 0004 规定第二阶段要引入以目录 / 仓库为单位的真 git，而 git 的模型就是「版本存在文件旁边」。现在就对齐，第二阶段是演进而不是推翻。
2. **版本与文件同生共死符合直觉。** 删掉一份笔记，它的历史跟着消失，不会在应用数据目录里留下孤儿。
3. **天然被用户已有的备份方案覆盖。** Time Machine、iCloud、Dropbox、以及用户自己的 git 仓库，备份笔记目录时会把历史一起带上。集中存储的方案则是「换台电脑历史就没了」，这对写作工具是硬伤。

## Considered Options

- **集中存放在 `appDataDir()`，按文件路径索引** —— 否决。不污染用户目录是它唯一的优点，但换电脑、重装系统即丢失历史，且用户在 Finder 里移动文件后版本会成为孤儿。
- **集中存放 + 内容寻址**（同时记录内容哈希，文件移动后重新认领）—— 否决。属于过度设计：内容寻址解决的是集中存储自己制造的问题。

## Consequences

- 会在用户的笔记目录里创建隐藏目录。这是已知代价，不是疏忽。
- 用户在应用之外移动或重命名文件时，历史不会自动跟随，会断在原处。当前阶段接受这一点，不做文件系统监听。
- 用户的目录若本身在 git 仓库中，`.milktown/` 是否应加入 `.gitignore` 由用户自行决定，应用不代为修改用户的 git 配置。
