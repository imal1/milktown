# 光标所在段的 Markdown 标记是画上去的，不是文档的一部分

光标进到哪一段，那一段的 Markdown 标记就显出来——`##`、`**`、`` ` ``、`[]()` 这些平时被排版吃掉的字符重新可见，可以直接改。这是 Typora 的核心手感，也是「所见即所得」与「你在写 Markdown」两件事能同时成立的原因：标记本身就是操作入口。

实现上，这些字符是 ProseMirror 的 **widget decoration**——画在文档上面，不在文档里。序列化时它们天然不存在，`read()` 读出来的还是原来那份文本。

## Considered Options

- **让文档真的持有那些字符，靠 CSS 隐藏** —— 纸面上看到的和 `read()` 读出来的完全一致，听起来更诚实。但它等于把 Markdown 标记变成文档内容：`**` 成了段落里两个真的字符，schema 要接受它们，输入规则要避开它们，保存前要清洗它们。`withoutEmptyParagraphs` 已经是这一类债了，那是被逼出来的一处；这一条是主动再欠一大笔。拒绝。
- **widget decoration** —— 采纳。

## Consequences

标记不可被选中、不进剪贴板、不算进字数——因为它们不是内容。要改一个标题的级别，改的是 `#` 后面那个文档节点的属性，不是那两个字符本身；点击标记的行为要单独接，不能指望编辑普通文本那一套。

粒度是**段**，不是视觉行。ProseMirror 认的单位是块，一个段落在 535px 的纸上会折成好几行，按视觉行做要自己算每行位置，段落中间折行处标记会跳。设计文案里的「光标进到哪一行」按这个口径读作「哪一段」——这也让它和「原文对照」的段段对齐用上同一个单位。

输入法期间冻结：`compositionstart` 到 `compositionend` 之间不切标记的显隐、也不更新字数。候选框还开着的时候纸面不许动，否则拼音串每敲一下都在推挤当前段。
