# 版本历史做成时间机器，不是 git

milktown 的版本功能是**自动时间机器**：保存时自动留存一个版本，用户不写提交信息、不管分支、不接触任何 git 概念。第一阶段只支持**单个文件**的历史。

否决真 git 的理由是产品定位（见 `CONTEXT.md` 与 ADR 0001）：本项目自用优先，验收标准是「作者今天愿意用它写东西吗」。git 的手动提交对代码是对的——一次提交对应一个逻辑变更；对散文是错的——写作没有「逻辑变更」这种边界，被要求写提交信息会打断心流。

## 分期

这是**分期，不是永久排除**：

1. **当前阶段** —— 时间机器 + 单文件历史。
2. **后续阶段** —— 支持以目录 / 仓库为单位的版本，届时再引入真 git。

因此当前阶段的存储格式必须为「以后能接真 git」留门，不得做出会阻断该路径的设计（这也是 ADR 0005 选择把版本存在文件旁边的原因之一）。

## 触发时机

- 保存（⌘S）时留存一个版本。
- 距上一个版本不足 **5 分钟**时覆盖它，不新增——⌘S 多数时候是肌肉记忆，不是「我要记一版」的意图表达。
- **例外**：打开文件时、关闭文件前各强制留存一版，不受 5 分钟窗口限制。这两个时刻是天然边界，值得单独留痕。

### 补记：这两版都不在「那一刻」落盘

原文说打开时留存一版，实现时发现它会让**只打开看一眼**的文件也在用户目录里长出 `.milktown/`。因此：

- **打开时**：只在内存里记下「打开时那一版」（内容 + 打开时刻），不写盘。等这个文件第一次被 ⌘S 保存时，把它作为一版补写进去，**时间戳仍归打开那一刻**，且强制新增不参与 5 分钟合并。于是历史里既有「我改之前它长什么样」，用户目录又不会被从未保存过的文件污染。
- **关闭时**：只在这个文件**已经有历史**（`.milktown/` 已存在）时才留存。从未保存过的文件，关窗不建目录——包括选了「不保存」而丢弃的内容。

代价是：打开一个文件、改了很多、然后选「不保存」关掉，这些改动不会进历史。用「保存过的文件才有历史」换「不碰没保存过的文件所在的目录」。

## Consequences

- 版本存的是完整内容而非增量。单个 Markdown 文件的体积下，为省空间做增量存储是过早优化。
- 「真 git」和「目录级版本」在当前阶段被明确排除。收到相关需求时，先确认是否到了第 2 阶段，不要顺手加进第 1 阶段。
