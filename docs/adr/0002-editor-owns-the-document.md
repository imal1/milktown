# 编辑器是文档的唯一真相源

文档内容只存在于 Crepe 编辑器实例内部。Vue 的响应式状态只持有当前文件路径、脏标记和文件名，**不持有文档内容**。保存时才通过编辑器 API 取出 Markdown；打开另一个文件时销毁旧实例、以新内容创建新实例。

这条决定是对原实现失败原因的直接回应：原代码让 React state 和 Milkdown 各存一份内容并试图双向同步，结果两个方向都错了——编辑器的变更从未接回 React（`onChange` 收下了却从未注册 listener），而回写方向用了 `defaultValueCtx`，那个值只在编辑器创建时读取一次。后果是脏标记永远为 false、保存写出的是初始字符串。

## Consequences

- 打开新文件会重建编辑器实例，撤销历史随之清空。这是可接受的：跨文件的撤销本来也没有意义。
- 脏状态由编辑器的文档变更事件置位、由成功保存清零，不做内容比对。
- 任何「让 Vue 侧也存一份 markdown 字符串」的改动都是在恢复已知会失败的设计，不要做。
