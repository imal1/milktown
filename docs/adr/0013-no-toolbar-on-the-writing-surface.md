# 写作面上没有工具栏

写作时手碰到的只有纸和字。Crepe 自带的两条浮动工具栏——选中文字浮出的格式条（`Feature.Toolbar`）与行首的拖拽手柄加斜杠菜单（`Feature.BlockEdit`）——全部关闭，18 条排版命令改由 macOS 原生菜单栏的「格式」与「段落」两栏承担，每一项带快捷键。

设计稿从一开始就写着「这个应用不要工具栏」，实现里却把 Crepe 的十个 feature 原样全开了。这份 ADR 记的不是一次改主意，是把已经定过的事钉住，免得下次有人看见 Crepe 有现成的工具栏就再打开一次。

## Considered Options

- **留着 Crepe 的控件，只改 CSS 变量和文案** —— 最省事，但它们的位置问题改不动：格式条浮在选区上方压着上一行；行首手柄在 560px 宽的窗口下真鼠标悬停完全不出现，等于那两个功能在窄窗口里不存在。而且格式条里没有标题、没有列表、没有引用——写 Markdown 最常用的三件事一件都不给，Σ 反而排在链接前面。拒绝。
- **关掉 Crepe 的，自己做浮层和斜杠菜单** —— 位置和文案的问题一次解决，但那是在建第二套排版入口，而菜单栏那一套无论如何都得有（它是可发现性的唯一落点，ADR 0011 一路的判断）。为一个不该存在的东西写两套。拒绝。
- **关掉，命令进原生菜单** —— 采纳。

## Consequences

排版命令的清单变成了跨语言的契约：`src/editor/format.ts` 里的 `FormatCommand` 与 `src-tauri/src/lib.rs` 里的 `MenuItem` id 必须逐字相同，对不上的话菜单点下去会静默地什么都不做，两边各自的测试都抓不到。`src/editor/format.daily.test.ts` 里有一条测试读 `lib.rs` 的源码来守这件事。

关掉的只是两条**工具栏**。跟着具体内容走的控件——链接气泡、表格把手、代码块语言选择器、图片、公式——都还在，它们只在碰到那个东西时才出现，不是常驻的。
