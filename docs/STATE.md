# Milktown — 进度快照

写于 2026-09-19，基于本分支 `feat/windows-drafts-source-mode` 的实际源码。

这份文档记录的是**代码实际做了什么**。它最初（2026-09-03）是一份停工快照，用来对抗
README 里已经不成立的完成度声明；那一版描述的 React 骨架已经整个被重写掉，内容见
git 历史。README 现在与代码一致，所以这份文档的职责改成一件事：**说清楚哪些做完了、
哪些没有、以及没有的那些为什么。**

## 一句话状态

一个能日用的所见即所得 Markdown 编辑器：真实文件读写、多窗口、自动版本留存、源码模式、
三个双页视图，写作面上没有工具栏。

## 做完了的

按 ADR 编号，每一条都有会变红的测试：

- **文档与文件**：编辑器是唯一真相源（0002）、打开 / 保存 / 另存为、当前文件路径。
- **版本**：保存时自动留存，版本存在文件旁边的 `.milktown/`（0004、0005），行级差异与还原。
- **规范化**：所见即所得的保存路径写规范化文本，不动点约定（0006、0008）。
- **源码模式**：⌘/ 是真相源的一次交接，不是第二份文档（0009）；此路径的保存不经规范化。
- **草稿**：从未保存过的文档关窗时留存，下次启动装回来，仍然是脏的（0010）。
- **多窗口**：一个窗口一个文档；Finder 双击与命令行开新窗口，拖拽与 ⌘O 装进当前窗口；
  同一文件已开则静默聚焦（0011）。
- **写作面去工具栏**：两条 Crepe 工具栏关闭，18 条命令进原生菜单，`format.daily.test.ts`
  读 `lib.rs` 源码守菜单 id 与命令清单逐字对齐（0013）。
- **光标行显源码标记**：行首标记悬挂在纸外，行内标记占位；输入法合成期间冻结（0014）。
- **三个双页视图**：原文对照 ⌥⌘/、磁盘对照 ⇧⌘/、版本对照 ⇧⌘H，与源码模式构成互斥组，
  进去之前真相源先交回编辑器；每个窗口挂自己的菜单以显示对钩（0015）。
- **界面**：34px 标题栏（文件名热区、脏点、字数与口径面板）、66ch / 18px / 1.8 的纸、
  最近文件面板、空文档的起手提示与最常用命令便条、拖拽悬停态、确认层、保存提示。

## 还没做的

| 缺口 | 为什么要紧 |
| --- | --- |
| **外部修改检测** | 文件在打开之后被别的程序改过时，⌘S 直接覆盖。这是唯一一条会丢别人数据的路径，代码里零实现。 |
| **排版面上的查找** | ⌘F 在写作视图会先切进源码模式（#26）。这是「没有工具栏」这条边界要付的钱，记成取舍不是遗漏。 |
| **深色模式** | Crepe 的 `frame-dark` + 另一套 CSS 变量，没开始。 |
| **本地相对路径图片** | 要走 Tauri 的 asset protocol，没开始。 |
| **目录级版本与真 git** | ADR 0004 明确的第二阶段，不在当前范围内。 |

## 测试手段的缺口

- **真输入法没验过**。`editor.daily.test.ts` 用 jsdom 的 `CompositionEvent` 驱动合成开始 /
  结束，守住了「候选框开着时纸面不许动、字数不更新」这条逻辑；但没有任何一层能驱动真正的
  拼音输入法。候选框与浮层打架这类问题，目前谁也不知道。
- **真机手过不在 `bun run check` 里**。`docs/agents/daily-usable.md` 的验收清单里那部分
  要在 `bun run tauri dev` 起的真窗口里逐条过，机器代不了。
- **doctest 不跑**。`cargo test` 换成了 `--lib --bins`：本机 rustdoc 撞 libz3 的版本缺口会
  SIGABRT，而全仓一条 doctest 都没有，`bun run check` 不该为它红。
