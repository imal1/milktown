# 能日用

这份文档是所有票的验收线。一张票在通过这里之前不算完成，无论代码写完没有。

## 为什么需要这条线

2026-09-05 之前，仓库有 141 个通过的测试、干净的 typecheck，和一个作为 Markdown
编辑器无法正常使用的产品。这不是巧合，是结构问题：

- 15 个测试文件全部跑在 node 或 jsdom 里，打的是纯函数和内存 port。
- `mountEditor` 是注入的依赖，所以 `workspace.test.ts` 一次都没跑过真的 Crepe。
- `tauri-ports.ts` 和 `lib.rs` 零测试。

于是有两类 bug 结构上不可能被抓到：编辑器自己的行为，和 Tauri 那一层。当天在
新加的日用回路里立刻抓到两条，两条都在 `read()`——也就是 ⌘S 写进磁盘的那份文本：

- 按 Enter 留一个空行，文件里会出现字面的 `<br />`。
- 文档以列表或引用结尾时，保存出去的文本末尾多一个空行，且
  `canonicalize(read()) !== read()`，违反 ADR 0006 的不动点约定。

线的作用不是多写测试，是让「能用」这件事有人守。

## 一条命令

```bash
bun run check
```

`typecheck` + `vitest run` + `cargo test`。提交前跑，票关掉前跑。

## 三层回路

| 层 | 在哪 | 守什么 | 用什么装配 |
| --- | --- | --- | --- |
| 逻辑 | `src/**/*.test.ts`（node） | 工作区流程、纯函数、状态机 | 内存 port + 假编辑器 |
| 编辑器 | `src/editor/editor.daily.test.ts`（jsdom） | 敲字、按键、保存出去的文本 | **真的 Crepe** |
| 原生 | `src-tauri/src/lib.rs` 的 `mod tests` | 启动参数、窗口注册表 | cargo |

三层的分工是刻意的：假编辑器那层验的是「工作区拿到内容之后怎么做」，看不见编辑器
本身；日用回路那层验的是「编辑器交出来的是什么」。两层都要有，缺一层就是当前这种
全绿但不能用的状态。

### 日用回路怎么写

`DocumentEditor` 上有 `type(text)` 与 `press(key, modifiers)` 两个动作，它们走的是
真的输入规则和真的 keymap——`type('# ')` 会变成标题，`press('Enter')` 会分段。
断言一律落在 `read()` 上，因为那就是保存会写出去的文本。

jsdom 上有一处已知偏差：ProseMirror 按 `navigator.platform` 决定 `Mod` 是 ⌘ 还是
Ctrl，jsdom 里认不出 mac，所以测试里用 `ctrlKey`。真机上两者都绑着。

## 验收清单

每张票关掉之前，逐条过。机器能跑的那部分已经在 `bun run check` 里，剩下的必须
在真实 Tauri 窗口里手过一遍——`bun run tauri dev`。

### 写作（每次改动都要过）

- [ ] 敲字、按 Enter 分段、⌘Z 撤销一步（不是清空整篇）、⇧⌘Z 重做
- [ ] `# `、`- `、`1. `、`> `、`**粗**`、`_斜_`、`` `码` `` 六条输入规则生效
- [ ] 中文标点、破折号、全角字符原样保留
- [ ] 从别处粘贴一段文本，格式没有炸
- [ ] 长文档（> 500 行）滚动流畅，工具条不错位

### 文件（碰到 `files/`、`workspace/` 时要过）

- [ ] ⌘S 保存已有文件；⇧⌘S 另存为；新文档 ⌘S 走另存为
- [ ] 打开又原样保存，`git diff` 是空的——文件没有被动过
- [ ] ⇧⌘O 打开对话框；⌘O 最近文件；拖一个 `.md` 进窗口能开
- [ ] 打开家目录以外的文件（外置盘、`/tmp`）——见下面的已知缺口
- [ ] 脏文档关窗会问；新文档关窗留草稿，下次启动装回来

### 窗口（碰到 `windows/`、`lib.rs` 时要过）

- [ ] 一个窗口一个文档；开一个已经开着的文件只聚焦，不开第二个
- [ ] ⌘Q 逐个走完每个窗口的脏文档处理，不跳过
- [ ] 菜单项落在眼前那个窗口，不广播

## 已知缺口

在这里登记，不散在票里。修掉时连同这一条一起删。

- **空列表项写成 `<br />`**：正确的写法是单独一个 `-`。
  `editor.daily.test.ts` 里有一条 `it.fails` 钉着它，修好那条会自动变红提醒删除。
- **fs 权限限死在 `$HOME/**`**：见 `src-tauri/capabilities/default.json`。
  家目录以外的文件（外置盘、`/tmp`、别处挂载的仓库）读不了。放宽是改安全姿态，
  需要单独决定。
- **不检测文件在打开之后被别的程序改过**：`workspace.ts` 的 `save()` 直接覆盖。

## 票的完成定义

1. `bun run check` 全绿。
2. 这张票碰到的那几组验收清单，在真实 Tauri 窗口里手过一遍。
3. 这张票修的行为，在三层里的某一层有一条会变红的测试钉着它。
4. 新发现但不在本票范围的缺口，登记到上面的「已知缺口」，不新开票。

第 3 条是重点：修完一个 bug 却没有留下会变红的东西，等于没修——下一次它会以同样
的方式回来，而全绿的测试套件会替它打掩护。
