## 需要设计产出的东西

按重要性排。前两项是全新界面，其余多为文案或状态补充。

### 1. 源码模式（全新画板，最重要）

⌘/ 从所见即所得切进来，再按一次切回去。这是整轮里唯一的新主视图。

需要定的：

- 用什么字体和字号 —— 现有 `--mono` 是 IBM Plex Mono，但正文一直是 Source Serif 4，源码模式突然全等宽是不是太跳。
- 要不要行号。目前倾向不要（双页视图的行号是另一票，README 里还挂着 TODO）。
- 纸张宽度是否与写作视图一致，还是源码模式放宽。
- 切换有没有过渡动画，还是硬切。
- 标题栏要不要有「当前在源码模式」的指示 —— 如果没有，用户按了 ⌘/ 之后靠什么认出自己在哪个模式？（提示：源码模式下 ⌘S 保存的是原文、不经过规范化，这个差异是有后果的，值得被看见。）

### 2. 查找替换条（全新组件）

只出现在源码模式里。⌘F 触发；如果当时在写作视图，会先自动切进源码模式再弹出来。

需要定的：位置（顶部浮条 / 贴在纸张上方 / 底部）、查找与替换两个字段的布局、「第 3 个 / 共 12 个」这类计数的呈现、「替换」与「全部替换」两个动作的形态、Esc 关闭的提示、以及匹配项在正文里的高亮色（现有 `--highlight` 是 `#f0ece2`，当前匹配项需要一个更强的第二色）。

### 3. 拖拽文件悬停态（全新状态）

文件被拖到窗口上方还没松手时，窗口要给出反馈。需要定的：是整页覆盖一层，还是纸张边缘高亮，还是标题栏变化。另外要考虑当前文档是脏的这种情况 —— 松手之后会先弹保存确认，悬停态本身要不要预告这件事。

### 4. 菜单栏文案表（只要文案，不要像素）

macOS 菜单由系统绘制，设计不需要画，但中文文案和分组要定死。四组的初稿如下，请确认或修改：

- **milktown**：关于 milktown、退出 milktown
- **文件**：新建、打开…、最近文件、保存、另存为…、关闭窗口
- **编辑**：撤销、重做、剪切、复制、粘贴、查找与替换…
- **视图**：源码模式、版本历史

快捷键沿用 `README.md` 里那张表，不新增也不改动。编辑组的前五项用系统预置项，文案由系统给，不用定。

### 5. 保存冲突确认（复用现有确认层，新文案）

`src/components/ConfirmLayer.vue` 已经是三选一的形态（保存 / 不保存 / 取消，对应 `⏎` / `⌘D` / `Esc`）。保存时发现文件在磁盘上被改过，用同一套壳，三个选项换成**覆盖 / 另存为 / 放弃**。需要设计给的是：问句怎么写（要让人明白「你打开之后，别的程序改过这个文件」），三个键位怎么分配。

### 6. 重复打开同一文件的反馈

第二次打开一个已经开着的文件时，应用会聚焦那个已有窗口而不是新开一个。需要定的是：有没有反馈，还是静默聚焦。（倾向静默 —— 窗口跳到眼前本身就是反馈。）

### 7. 草稿恢复提示（复用现有 toast，新文案）

启动时若存在上次被丢弃的未保存草稿，直接把内容装进编辑器，配一条 toast。现有 toast 样式在 `src/App.vue` 的 `.toast` 里（深色小胶囊，居中偏下，1.8 秒后消失）。需要定的是文案，以及 1.8 秒对这条信息够不够 —— 它比「已保存」重要得多，用户错过就不知道自己手上这份是恢复来的。

另外有个优先级要说清：**空状态（列最近文件）和草稿恢复是互斥的**。有草稿时编辑器里有内容，空状态不出现。如果这次启动是双击文件进来的，文件优先，草稿留着不动。

### 8. 相对路径图片在正文里的样子

`![](./img/a.png)` 这类相对路径图片终于能显示了。需要定的：图片的最大宽度（是否顶到纸张宽度）、有没有边框或圆角、上下留白、以及**路径写错时显示什么** —— 这个失败态一定会遇到，别留空。
