# 交接文档：写作面上不要工具栏

给 Claude Design。写于 2026-09-05，第二版——第一版问的那个决定已经定了，这版记录定了什么、代码已经动了哪些，以及还剩什么要画。

## 定了什么

**写作面上没有工具栏。** 排版命令全部搬进系统菜单栏，写作时手碰到的只有纸和字。这是 Typora 的路。

第一版简报给了三个选项：甲（保留 Crepe 的浮动控件，只改配色）、乙（关掉它们，命令进原生菜单）、丙（关掉 Crepe 的，自己重做浮层）。**选的是乙。**

理由是设计稿自己已经写过——第 219 行：「不通栏，不吸顶——通栏会让它看起来像工具栏，而这个应用不要工具栏。」实现里却开着两条工具栏，那是实现走偏了，不是设计要改。

## 代码已经改成什么样

这部分是既成事实，设计不用再考虑它们的存在。

- `Feature.Toolbar`（选中文字浮出的格式条）与 `Feature.BlockEdit`（行首 `+`、拖拽手柄、斜杠菜单）**已关闭**。
- 18 条排版命令收在 `src/editor/format.ts` 里，是一份纯字符串清单。
- 原生菜单加了「格式」与「段落」两栏，项目 id 与那份清单逐字对齐，每一项都带快捷键：
  - **格式**：加粗 ⌘B、斜体 ⌘I、行内代码 ⇧⌘\`、删除线 ⇧⌘X、超链接 ⌘K
  - **段落**：正文 ⌘0、标题 1-6 ⌘1-⌘6、无序列表 ⌥⌘U、有序列表 ⌥⌘O、引用 ⌥⌘Q、代码块 ⌥⌘C、表格 ⌥⌘T、分隔线 ⌥⌘-
- 44 条测试钉着这三件事：每条命令真的改得动保存出去的文本、写出来的 Markdown 是什么样、两条浮动工具栏确实不在 DOM 里。菜单 id 与命令清单对不上时测试会红。

所以第一版简报里的第 1、2、3、5、8 条——格式条缺标题列表引用、格式条盖住上一行、行首手柄窄窗口下消失、斜杠菜单向上弹盖住正文、菜单里没有排版命令——**这五条随控件一起消失了**。

第 4 条（斜杠菜单是英文的）也跟着消失，但它背后的问题没消失，见下面「新出现的问题」。

## 还留在桌上的两条

### 标题栏的文档菜单按钮只有 17px 高

标题栏 34px，左侧给交通灯留 72px，中间是文件名，右边是字数。

文件名是一个 `<button>`，键盘能到——但高 17px，后面的 `▾` 只有 6×13px。脏标记是紧贴文件名的一个 `*`。

- **VSCode** 状态栏项：视觉上很小，但点击区域上下撑满整条状态栏。

**要设计的**：点击区域的边界（视觉尺寸可以小，热区不行）、悬停与聚焦的反馈、脏标记的形态。

### 字数是 11px 的浅灰，而且是字符数

右上角 `#A39B8E` 11px 压在米色上，几乎读不出来。而且它数的是**字符数**，标签一个字都没有——`241` 是什么，看的人不知道。

- **Typora** 的字数在右下角状态栏，点一下展开：字数、字符数、行数、阅读时长。
- **VSCode** 状态栏每一项都可点、都有 hover 提示。

**要设计的**：这个数字的口径要写在界面上，以及它值不值得能点。

## 新出现的问题

拿掉工具栏本身会造出三个新问题。这三条是这一版设计的主要工作。

### 1. 没有工具栏之后，人怎么知道能做什么

菜单栏里全都有，但菜单栏要主动去拉。第一次打开这个应用的人，看到的是一张空白的纸。

设计稿第 350 行说过「菜单是唯一能让人『发现』⌘/ 存在的地方」。现在菜单要承担的发现量比那时候大得多——它得同时让人发现 18 条排版命令。

- **Typora** 的做法：占位文字之外什么都不给，靠菜单栏和帮助文档。它赌用户已经会 Markdown。
- **VSCode** 的做法：空编辑器里列出最常用的几条命令和它们的快捷键，一旦开始打字就消失。

**要设计的**：空文档状态给什么。现在只有一句占位文字「开始写」。

### 2. 光标所在行要不要显示源码标记

Typora 的核心手感就是这个：平时看到的是排好版的样子，光标移进那一行，`##`、`**`、`` ` `` 这些标记显出来，可以直接改。它靠这个把「所见即所得」和「你在写 Markdown」两件事同时成立，也因此不需要工具栏——标记本身就是操作入口。

Milktown 现在没有这个行为。加粗的字就是粗的，看不见 `**`，只能靠 ⌘B 或者重新打一遍。

**要设计的**：这个行为要不要有。有的话，标记用什么颜色/字重/透明度显示，才既能读又不打断阅读节奏。这是这一版里唯一会改变「写字时纸面长什么样」的一条，也是最值钱的一条。

### 3. 链接、表格、代码块还是有浮动控件

关掉的是两条工具栏。这些还开着，它们跟着具体内容走，不是常驻工具栏：

- `Feature.LinkTooltip`——点链接浮出的地址气泡
- `Feature.Table`——表格的行列把手
- `Feature.CodeMirror`——代码块右上角的语言选择器
- `Feature.ImageBlock`——图片的插入与调整
- `Feature.Latex`——公式

它们全都还是 Crepe 的 Material Design 白卡片和无衬线图标，落在米色衬线纸面上。`src/styles.css` 整包 import 了 Crepe 的 `frame.css`，只覆盖了九个颜色与字体变量。

**要设计的**：这五个控件的皮。它们不违反「不要工具栏」——只在碰到那个东西时才出现——但它们现在不属于这张纸。

## 两条已经排除的

**打字延迟不是问题**。15000 字、455 个块的文档，每一次按键 1.82ms（小文档 0.75ms，2.4 倍）。每键全文序列化这笔开销真实存在，但量级无所谓。不需要为性能改设计。

**中文输入法没验**。代码里 `composition` 零匹配，四层测试回路里也没有任何一层能驱动输入法。这是测试手段的缺口，不是设计问题——但它意味着，中文输入下的任何交互（候选框与浮层打架、拼音串被算进字数）目前谁也不知道。设计如果依赖输入过程中的实时反馈，要先知道这一点。

这一条对上面的「新问题 2」尤其要紧：光标行显源码标记，会在输入法候选框还开着的时候就开始跳动。
