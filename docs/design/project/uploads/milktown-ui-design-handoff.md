## 设计的边界条件

这些是上一轮定死的，直接约束你能设计什么：

**产品定位**：自用优先，能发布算副产品。验收标准是「作者今天愿意用它写东西吗」。不为假想用户设计，不做设置界面、引导流程、空状态营销文案这类为陌生用户准备的东西。

**单文档模型**：一个窗口一个文件。**没有侧边栏文件树，没有标签页。**「最近文件」列表是应用里唯一的多文件入口。想开第二个文件就开第二个窗口。

**所见即所得**：Milkdown Crepe。**不是双栏源码 + 预览**——这条路被明确否决过（见 ADR 0001）。不要再提议加源码视图或分屏预览。

**桌面应用**：Tauri 2，作者在 macOS。当前窗口 800×600（这个尺寸可以改，没人守着它）。

## 关键约束：可设计的表面比想象中窄

Crepe 自带一整套编辑辅助 UI，十个 feature 全开：

斜杠命令菜单、块拖拽手柄、选中文字浮出的格式工具条、CodeMirror 代码块（含语言选择器）、表格操作手柄、图片块、链接悬浮气泡、任务列表复选框、KaTeX 公式、占位提示。

**这些不在设计范围内。** 它们是 Crepe 的既有实现，只能通过主题和 CSS 覆盖调整外观，重新设计它们的交互等于放弃 Crepe——而放弃 Crepe 的代价上一轮已经算过并否决了。

Crepe 自带六套主题可选：`crepe` / `crepe-dark` / `frame` / `frame-dark` / `nord` / `nord-dark`。

**真正需要设计的，是编辑器之外的那一圈**：窗口 chrome、文件操作的入口、当前文件名和脏状态的呈现、最近文件的入口、主题与深色模式、新建文档时的空状态。

## 需要这次设计会话回答的问题

以下都是开放的，上一轮没碰：

1. **工具栏留不留。** 旧实现有一条横贯顶部的工具栏，四个按钮（新建/打开/保存/另存为）加文件名。但一个自用的所见即所得编辑器，这四个操作全都有快捷键，工具栏可能纯粹是在偷写作区域的高度。备选形态：完全去掉走系统菜单栏、悬停才出现、极简状态条。
2. **脏状态怎么表达。** 旧实现是文件名后面加一个 `*`。
3. **最近文件的入口形态。** 下拉菜单？新建文档时的空状态列表？还是只走快捷键 + 系统菜单？
4. **深色模式。** 跟随系统，还是手动切换，还是不做。Crepe 的六套主题里明暗是分开的两套。
5. **主题选哪套，还是自定义。** 六套现成的够不够，还是要写自己的 CSS 覆盖层。
6. **窗口形态。** 标准窗口边框，还是 Tauri 的无边框 + 自绘标题栏（macOS 上后者更常见于写作类应用）。
7. **写作区域的排版。** 行宽上限、字体、行高、页边距——这是一个写作工具最影响日常体验的部分，也是最值得花时间的部分。
